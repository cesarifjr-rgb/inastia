# Contrat des effets intégrés

Sources : `src/motion.ts`, `motion.css`, `service-art.css`, `portfolio-client.ts`. Les effets utilisent CSS, IntersectionObserver et le dialogue natif ; aucun moteur GSAP, canvas, vidéo, WebGL ni défilement intercepté. Les interactions natives retenues ont été exercées sur Chrome, Firefox et WebKit ; voir [revue technique](technical-review.md).

Les coûts ci-dessous renvoient aux [21 traces de la page finale](performance.md) : trois répétitions, Chrome 152, 1440 × 1000, DPR 1, CPU ×4. Il s’agit du travail principal médian de toute la fenêtre observée, pas du coût isolé d’un élément ni d’un temps par frame. Le coût mobile précis des effets n’a pas été profilé séparément ; le chargement mobile dispose d’un run Lighthouse.

Hors écran, les trois boucles sont en pause : phases et transformations strictement inchangées sur les trois fenêtres de 1,06 s ; zéro Paint/Layout. Le thread principal conserve un travail de mesure médian de 3,31 ms. La visibilité masquée a aussi un test comportemental avec événement simulé ; une bascule native d’onglet n’est pas revendiquée.

Le bouton Animations est conservé. La préférence système initialise l’état ; une action explicite permet la reprise, et un changement ultérieur de préférence est traité. Sans JavaScript, les illustrations sont dessinées mais leurs boucles restent en pause. Un retour BFCache réel est testé ; lors d’un abandon de document, les observateurs et écouteurs du contrôleur sont libérés. Les contrôles du guide et du formulaire ne dépendent d’aucun de ces effets.

Les prototypes concurrents étaient une translation et un découpage progressif du même atlas. Le choix et leurs traces isolées figurent dans `design/explorations/motion.md`. Les coûts des prototypes et ceux de la page complète ont des périmètres différents et ne sont pas présentés comme interchangeables.
